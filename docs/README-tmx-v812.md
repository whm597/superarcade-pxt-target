# SuperArcade 编辑器：导入 Tiled 瓦片地图（.tmx/.tsx → 资产）

## 这是什么

在 SuperArcade 定制 MakeCode Arcade 编辑器中新增「导入 Tiled 地图」功能：
- 顶部工具栏「导入图片」按钮右侧新增按钮 **「导入Tiled」**（固定右上角，与「导入MIDI」同排）
- 选择 Tiled 工程文件（`.tmx` 或 `.tmj` 地图 + `.tsx`/`.tsj` tileset 定义 + `.png` 瓦片图片）
- 解析转换后 **直接写入编辑器资产管理器**（瓦片 tile 资产 + 地图 tilemap 资产），无需手动粘贴 jres（编辑器内 jres 是只读文件，粘贴不通，所以做成按钮直接入库）

## 使用方法

1. 打开编辑器，顶部工具栏「导入图片」按钮右侧出现 **「导入Tiled」** 按钮
2. 点击按钮 → 选择文件（可多选）：
   - 必需：地图文件 `.tmx`（XML）或 `.tmj`（JSON）
   - 可选：tileset 定义 `.tsx`（XML）或 `.tsj`（JSON）——若 tmx 里是**外部引用**（`<tileset source="...">`）则必须同时选择；**多 tileset 可一次选择多个 .tsx**
   - 必需：tileset 图片 `.png`——**多 tileset 时按文件名自动匹配**（tsx 里 `<image source="xxx.png">` 的文件名 ↔ 所选 PNG 的文件名一一对应）
3. **弹出「选择目标瓦片尺寸」对话框**：
   - 显示**原尺寸**（如 `40px × 40px`）
   - 提供**像素输入框**（默认 16）与 4/8/16/32px 快捷按钮
   - Arcade 编辑器/运行时只支持 **4 / 8 / 16 / 32px**（这是 pxtlib 的硬编码枚举，无 20/24/40 等中间值）；非标准尺寸（如 40px）必须缩放后才能在地图编辑器使用
   - 缩放为**面积平均（box 滤波）重采样**（保留像素风与砖缝等 1px 细线），瓦片与地图同时缩放、格数引用同步换算
   - 输入非法尺寸会红字提示，点「取消」放弃导入
   - **「导入碰撞」checkbox（默认勾选，可取消）**：勾选后展开碰撞来源——①**图块属性**（tsx `collision`/`solid` 为 true 或数值>0 的瓦片格子 → 墙）；②**碰撞图层多选**（列出地图全部图层，按 Tiled 面板顺序从上到下，可多选；选中图层的非空格子 → 墙）。两者并存取并集。取消则不写碰撞
4. 导入成功提示：`瓦片 N 个（图集全量），地图用到 M 种` + 翻转烘焙数 + 碰撞格数（分图块属性/图层统计）+ `地图资产：level1` + 缩放说明
5. 到「资产」面板查看；打开地图资产后，**瓦片会出现在地图编辑器的 My Tiles 中**（只有选中/打开地图后 My Tiles 才加载该地图用到的瓦片集合）

只导 tileset 不导地图也可以：只选 `.tsx` + `.png`，同样会先弹缩放对话框，再把 tileset 里**所有 tile** 导入为瓦片资产。

## 支持范围

| 项目 | 支持 |
|---|---|
| 地图格式 | Tiled 正交（orthogonal）地图，`.tmx` XML / `.tmj` JSON |
| tileset | 外部引用（.tsx/.tsj）与内嵌 tileset；**多 tileset 集合**：一个地图引用多个 tsx，各自按文件名匹配对应 PNG（尺寸必须一致）；自动按 firstgid 合并 |
| 瓦片尺寸 | 正方形 tile；导入时可选择目标尺寸 4/8/16/32px（原尺寸非标准则强制缩放） |
| 图层数据 | CSV、base64、base64+zlib、base64+gzip；无限地图（chunk） |
| gid 处理 | 自动紧凑重映射（1..N），透明像素 → 透明 tile |
| **翻转位** | **完整烘焙**：gid 高位标志 H（水平）/V（垂直）/D（对角）按 Tiled 官方顺序（D→H→V）做像素变换，生成独立烘焙瓦片（bit29 已清除）；地图里用了翻转的格子自动引用对应烘焙瓦片 |
| **碰撞** | ①图块属性 `collision`/`solid`（bool 或数值 >0）②**碰撞图层多选**（选中图层非空格子）→ 墙（值 2=TM_WALL），写入地图碰撞层；导入时可选（默认勾选），两种来源并存取并集 |
| 颜色转换 | PNG → Arcade 16 色调色板（最近色匹配，半透明按透明处理） |
| 瓦片导入 | **全量导入**：图集所有瓦片全部入库（含地图未用到的） |
| 上限 | 瓦片资产数无上限（如 20×20=400 全量导入）；「地图用到的瓦片种类（含翻转组合）」受 Arcade 数据区索引上限 255 约束 |

## v8.9 新增功能（缩放对话框支持固定像素）

### 背景
v8.8 的缩放对话框只有「目标宽度 + 等比高度」。导入精灵图时按比例换算不直观——用户更想直接指定目标像素（如 16×16 / 32×32）来适配游戏精灵网格。

### 功能（对话框升级）
- **双输入框**：目标宽度 × 目标高度（均支持手输）
- **「保持宽高比」checkbox（默认勾选）**：勾选时改一边自动换算另一边（等比行为与 v8.8 一致）；**取消勾选可自由指定宽高**（非等比拉伸，如把任意图片直接缩到 16×16）
- **「精灵尺寸」快捷按钮**：16×16 / 32×32 / 64×64 / 128×128——点击后**自动解锁等比**并直接填入宽=高，一键适配游戏精灵
- 等比快捷（100%/50%/25%/12.5%）保留；非法输入红字提示；重采样仍是面积平均 box 滤波

### 验证
- jsdom 端到端 27 项（v8.8 的 22 项 + 新增 5 项：等比默认勾选、联动换算 200→150、取消等比自由指定 {16,16}、精灵快捷 32×32 自动解锁等比、精灵快捷确定返回 {32,32}）
- v8.7 全套件 16 项在 v8.9 合并版上零回归

## v8.8 新增功能（导入图片 / 导入动画 像素缩放选择）

### 背景
编辑器原有「导入图片」「导入动画」（右上角按钮与拖拽）导入大图时会强制按 320×240 比例拉伸（浏览器插值，像素风模糊、细节丢失）。现在给它们加上**与 Tiled 导入相同的像素缩放选择对话框**。

### 功能
- 点「导入图片」/「导入动画」（或拖拽图片进编辑器）→ 选文件后先弹 **「选择目标尺寸」对话框**：
  - 显示**原尺寸**（如 `320px × 240px`）
  - **目标宽度输入框**（默认原宽，即不缩放），**高度按比例自动换算**并实时提示
  - **等比快捷按钮**：100% / 50% / 25% / 12.5%
  - 非法输入红字提示，点「取消」放弃导入
- 缩放为**面积平均（box 滤波）重采样**（与 Tiled 导入一致，保留像素风与细线）
- **动画**：所有帧统一缩放到**第一帧决定的目标尺寸**（保持各帧一致）；帧间隔 prompt 与旧流程一致（默认 200ms）
- 导入后写入资产管理器（复用 TMX 模块的资产管理器查找），与旧功能共用「资源」面板
- **实现方式**：覆盖方案——克隆替换旧按钮（旧监听消失）+ capture 阶段拦截拖拽；**前 1294 行基线逐字节不变**（MD5 `77391f15…`）

### 验证
- jsdom 端到端 22 项：boxScale 面积平均像素级（2×2→1×1 混合平均正确）、pngToBitmap 调色板量化（红/白/透明索引正确）、对话框交互（默认原宽、50% 快捷、手输 200→{200,150}、非法红字）、按钮克隆替换（旧监听消失）、资产写入路径（createNewProjectImage / createNewAnimationFromData 经 __tmxImport 复用）

## v8.7 新增功能（碰撞图层多选）

### 为什么需要
- **真实素材（如 1-1.tmx）的碰撞信息往往在图层里，不在 tsx 图块属性里**：该素材的 tsx 没有任何 `collision`/`solid` 图块属性，`land` 层是地砖和水管、`wall` 层是金币和问号砖——v8.6 图块属性方案对这类素材导入后碰撞 0 格、实测无碰撞。
- **解决方案**：导入对话框新增「碰撞图层」多选清单（列出地图全部图层，按 Tiled 面板顺序从上到下），勾选的图层其**非空格子**（翻转标志剥离后 gid≠0）写入碰撞值 2=TM_WALL。
- 与图块属性方案**并存取并集**：两种来源任一命中即写墙；都未勾选则地图无碰撞。

### 使用建议
- 实体层（如 `land` 地砖/水管、`wall` 问号砖）勾选；背景/装饰层（`background` 天蓝、`scene` 云朵山丘、`writeflag`/`endflag` 旗帜）不要勾选。
- 金币若在 `wall` 层会被一并写成墙（素材图层语义由 Tiled 作者决定），如需金币不挡精灵可在 Tiled 里调整图层或只用 `land`。
- 导入成功提示会分来源统计：`碰撞：已写入 图块属性 N 格，图层 M 格，共 K 格（值 2=墙）`。

## v8.6 新增功能（翻转位烘焙 / 多 tileset / 碰撞导入）

### 翻转位烘焙
- **背景**：Tiled 地图数据区（CSV/base64）里每个格子的 gid 高 4 位是翻转标志——`0x80000000` 水平翻转、`0x40000000` 垂直翻转、`0x20000000` 对角翻转（正交地图 = x/y 轴交换，实现 90° 旋转）、`0x10000000` 六边形旋转（正交地图忽略但必须清除）。此前这些标志会被当 gid 的一部分 → 格子错配。
- **实现**：解析 gid 剥离标志 → 按 Tiled 官方组合顺序（**对角先，再水平，再垂直**）对瓦片像素做逆变换 → 生成独立烘焙瓦片资产 → 数据区引用指向对应烘焙瓦片。地图里用到的每种翻转组合各占一个数据区索引（计入 255 上限）。
- **验证**：H/V/D 及组合翻转像素级正确（jsdom 端到端断言通过）。

### 多 tileset 集合
- 一个地图引用多个外部 tileset（多个 `.tsx`）时，**按文件名自动匹配**：tsx 里 `<image source="xxx.png">` 的文件名 ↔ 你选择的 PNG 文件名一一对应；匹配不到的 tileset 会在导入诊断里提示。
- 限制：地图内所有 tileset 的 tile 尺寸必须一致（Arcade 单地图单一 tile 尺寸）。

### 碰撞导入（可选，默认勾选）
- **来源**：tsx 的**图块属性**（Tiled 里给某个 tile 添加自定义属性 `collision=true` 或 `solid=true/1`），网格级精确、与图层无关。
- **映射**：属性为 true 或数值 >0 → Arcade 碰撞值 **2（TM_WALL）**，写入地图碰撞层（`layers.data`，行优先 4bpp，与官方 `Bitmap.fromData` 读取一致）。运行时 `isWall` 精确判定 `layers.getPixel === TM_WALL`，只有 0（可通行）/2（墙）真正生效。
- **UI**：导入对话框里 **「导入碰撞」checkbox 默认勾选**，取消则不写碰撞（全 0，行为与 v8.5 一致）。

## v8.5 修复内容（对应 v8.4 实测的新问题：云朵上半部分露出透明空洞）

### 背景空洞（Arcade 单层瓦片无图层叠加）—— 已修复
- **现象**：v8.4 实测瓦片全部匹配正确，但**云朵等瓦片内部未 100% 填充的部分露出透明空洞**（如云朵上半部分），原图里这些透明区域是由天蓝背景补充的
- **根因（Arcade 与 Tiled 的机制差异）**：Tiled 是**多图层叠加渲染**——background 层天蓝铺满（3520 格 gid85）+ scene 层云朵盖在上面 → 云朵瓦片内的透明像素透出下层天蓝，显示为"云朵嵌在蓝天里"。**MakeCode Arcade 的 tilemap 是单层瓦片索引**：一个格子只能存一个瓦片，云朵格子被云朵瓦片独占，瓦片内透明像素（f4 值 0）渲染时透出的是**地图底色**而非背景层 → 空洞
- **修复（导入时模拟背景层）**：convert 合并各图层后统计 gid 出现次数，**覆盖 >50% 格子的 gid 视为背景层**（本素材 gid85 天蓝）；把**地图用到的瓦片**的透明像素（boxAvg 结果为 0 的像素）**填成背景瓦片的平均色**（天蓝 rgb(95,151,255) → 调色板最近色 9 浅蓝，与背景瓦片显示一致）→ 云朵/山丘的透明部分在编辑器与游戏里都显示为背景色，不再空洞
- **边界**：仅对"地图用到的瓦片"填充（资产面板中未用到的瓦片保持原样）；未检测到明显背景层（无 >50% 的单一 gid）时跳过填充，行为与 v8.4 一致
- **验证**：
  - 云朵瓦片 tile360-362/tile380-382：**透明像素 0 个**（212/168/211/70/32/35 个像素填为天蓝，其余云朵主体保留）✓
  - 山丘瓦片 tile280-282：透明像素 0 个（透明部分填天蓝，山体保留）✓
